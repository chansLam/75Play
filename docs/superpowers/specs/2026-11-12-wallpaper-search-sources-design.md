# 壁纸搜索增加来源

本文件只改搜索。它替换 `2026-11-12-wallpaper-settings-design.md` 里关于搜索来源、搜索主机和搜索结果文案的段落。每日壁纸、三种显示模式、自定义文件和壳层铺图保持原样。

## 行为

搜索对话框仍是一个网格，最多 24 张。点搜索后，三个源同时请求：

- 必应图片搜索
- Wallhaven
- 极简壁纸（`bz.zzzmh.cn`）

关键词去掉首尾空白后为空，则三个源都不请求，正文保持「输入关键词」。

谁先有合格的图，谁先出现。必应的图后到时插到网格最前面，另外两个源的格子往后顺，超出 24 张的从末尾去掉。必应已经有 24 张合格图时，取消 Wallhaven 和极简壁纸。Wallhaven 或极简壁纸先凑满 24 张时不取消必应，必应的图仍然插到前面并截断末尾。

一个源失败只丢掉它自己的结果。已经显示的图保留。一张图都还没有、而且还有源没结束时，继续显示加载。已经有图时，加载留到其余源结束或被取消。

全部结束后仍然一张都没有：

- 至少有一个源正常返回，只是没有合格图：显示「没有找到壁纸」。
- 每个源都失败：显示「暂时无法搜索，请稍后再试」。

http 原图、尺寸不够、详情页打不开，都算这张图不合格，不算整个源失败。

点中一张的结果不变：下载原图，写入 `custom.jpg`，模式改为自定义，刷新壳层背景并关闭对话框。写入前再量一次原图像素，仍然不大于屏幕就不写入，对话框不关闭，只在这一张上标出「这张图片不够大」。每日来源的单选不动。

Colorhub、彼岸、Pexels、Pixabay、`bing.ioliu.cn`、堆糖和 Lively Wallpaper 不接入。

## 尺寸

比较用搜索开始时的 `displayMetrics.widthPixels` 和 `heightPixels`。把图片的两边和屏幕的两边都分成长边、短边。图片长边必须大于屏幕长边，短边必须大于屏幕短边。相等不要。宽或高不是正数的不要。不知道尺寸的不要。

这个条件只用于搜索。每日壁纸仍取来源的第一张合格图，不按屏幕尺寸丢弃。

## 来源

### 必应图片搜索

请求：

`https://cn.bing.com/images/async?q={UTF-8}&first=1&count=24&adlt=strict&qft=+filterui:imagesize-large`

`adlt=strict` 只要普通内容。`qft` 只是让必应偏向大图，不能代替上面的尺寸条件。

从返回的 HTML 里读取每条 `m="{...}"`。使用其中的 `murl` 和 `turl`。`murl` 不是 https，或带有 userinfo 的，丢掉。`turl` 必须是 https，且主机是 `bing.com`、`www.bing.com` 或以 `.bing.net` 结尾；否则用 `murl` 当缩略图。这条结果没有宽高。进网格前下载 `murl`，只用 `BitmapFactory.Options.inJustDecodeBounds` 读取宽高，不把这次下载的字节留到点击时。不够大的丢掉、不显示。合格图凑满 24 张，或对话框关闭时，停止继续下载。点击时按 `murl` 再下载一次，写入前再量尺寸。

### Wallhaven

搜索地址保持现在的写法：`purity=100`、`categories=100`、`sorting=relevance`、`atleast=1280x720`、`page=1`，关键词 UTF-8。这些参数只负责向服务器要普通内容。进网格前再用 `dimension_x` 和 `dimension_y` 做尺寸判断。缺尺寸或不够大的丢掉。

合法 JSON 且 `data` 是数组，但没有一张同时通过主机和尺寸条件时，搜索算空结果。缺 `data` 或不是 JSON，算这个源失败。每日壁纸继续调用不含尺寸条件的解析，避免把「第一张图不够大」变成每日下载失败。

### 极简壁纸

搜索页：`https://bz.zzzmh.cn/search?q={UTF-8}`。只读第一页。每张卡片要有指向 `/wallpaper/{id}` 的链接，以及 `https://imageai.zzzmh.cn/.../view/thumb/...` 的缩略图。

搜索页没有尺寸。对卡片打开详情页 `https://bz.zzzmh.cn/wallpaper/{id}`。使用带有 `on` 的那个分辨率按钮。它的 `data-tier` 用 `×` 或 `x` 分开两个正整数，例如 `1920 × 1200`。大图地址是 `https://imageai.zzzmh.cn/.../view/large/...webp`。选中尺寸和大图地址都有，而且尺寸大于屏幕，才进入网格。详情打不开、没有选中尺寸或没有大图地址的卡片丢掉。详情最多 3 个并发。必应已满 24 张或对话框关闭时取消。

点击后直接下载详情页给出的大图地址。

## 主机

搜索文档和 Wallhaven、极简壁纸的图片仍走固定主机。必应原图是解析出来的 https `murl`，主机可以在固定名单之外。证书校验保持开启，继续使用系统根证书加上现有的 `update_ca_bundle`。不关闭主机名校验。

固定名单在原有必应、`.bing.net`、Wallhaven 之外增加：

- `cn.bing.com`
- `bz.zzzmh.cn`
- `imageai.zzzmh.cn`

跳转规则：

- 搜索页、Wallhaven 图片、极简壁纸图片：跳转后的地址仍必须在固定名单里，且是没有 userinfo 的 https。
- 必应原图：跳转后必须仍是没有 userinfo 的 https。落到 http 或带 userinfo 的地址时，这张图失败。

不把壁纸客户端放宽成任意 https 都能请求。只有必应解析出来的原图走上面这条例外。

## 合并

网格顺序由一个不依赖 Android 的合并器计算。它接收三个源各自的结果：失败、空、或已经按尺寸筛过的图。可见列表是必应的图在前，其余的图按到达顺序接在后面，总数不超过 24。必应合格图达到 24 张时，合并器要求取消另外两个源。

界面只负责发请求、把尺寸合格的图交给合并器，并按合并器的列表刷新网格。

## 失败

| 情况 | 结果 |
|---|---|
| 关键词为空 | 不发请求，正文保持「输入关键词」 |
| 还有源未结束，且一张合格图都没有 | 显示加载 |
| 已有合格图，其余源还在进行 | 显示这些图，并保留加载 |
| 结束时有合格图 | 显示这些图。单个源失败不再盖住网格 |
| 结束时没有合格图，且至少有一个源正常返回 | 「没有找到壁纸」 |
| 结束时每个源都失败 | 「暂时无法搜索，请稍后再试」 |
| 点击后的原图下载失败或无法解码 | 只标记该张，模式不变 |
| 点击后原图不大于屏幕 | 只标记「这张图片不够大」，模式不变 |
| 必应原图跳到 http 或带 userinfo 的地址 | 这张图失败 |
| 其他请求跳到固定名单以外 | 这次请求失败 |

新文案键 `settings_wallpaper_too_small`，中文为「这张图片不够大」。写入 `values` 和全部 `values-xx`。

## 测试

单元测试不访问这三个网站。

- 尺寸：长边和短边都更大才通过。一边相等、一边更大不通过。宽或高为 0 不通过。横图对竖屏用长边对长边、短边对短边。
- 必应 HTML 能取出 https `murl` 和合格的 `turl`。http `murl` 丢掉。没有 `m` 记录的页面算空结果，坏内容算失败。
- Wallhaven 搜索：尺寸不够或缺少尺寸的条目不进入结果。数组里的图全部被滤掉时算空结果。缺 `data` 算失败。每日解析不使用屏幕尺寸。
- 极简壁纸搜索页能配上详情路径和 thumb 地址。详情页能取出选中的 `data-tier` 和大图地址。缺任何一项的卡片丢掉。
- 合并器：必应后到时排到最前；总数不超过 24；必应满 24 张时要求取消另外两个源；另外两个源先满 24 张时不取消必应。一个源失败、另一个源有图时，可见列表仍是那些图。三个源都失败时状态为失败。一个源空、其余失败时状态为没有找到。
- 必应原图的 https 地址可以通过图片例外。同一地址不能通过固定名单。`bz.zzzmh.cn` 和 `imageai.zzzmh.cn` 在固定名单里。http 和带 userinfo 的地址两种检查都不通过。

`SettingsTranslationsTest` 继续守住新文案出现在全部 `values-xx`。

## 不做

- 不改每日壁纸的来源、地址和更新规则。
- 不接入 Colorhub、彼岸、Pexels、Pixabay、`bing.ioliu.cn`。
- 不做分类浏览，不翻到搜索结果的第二页。
- 不保存必应用于量尺寸的那次下载。
- 不关闭证书校验，不用手机自带 curl 缺证书来放宽信任。
- 不增加 API 密钥、动态壁纸或按壁纸取色。

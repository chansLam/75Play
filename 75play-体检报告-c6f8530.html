六、架构关键发现

  • 模块方向干净：Gradle 无 shared→common 反向依赖、无循环；但存在 split package（shared/common 共用 com.shihab.diplay 根包），且 mobile/build.gradle.kts:110 绕过 common 直连 shared。
  • 上帝类：CarPlayHostActivity.kt 2161 行 / 98 方法 / 249 字段；CarPlayController.kt 2009 行 / 83 方法；DiPlayActivity.kt 1348 行。协议栈 Session 以下接口边界清晰（AirPlaySessionListener 等），但 orchestration 层零抽象，三方直接 new 2009 行具体类。
  • 反常依赖方向：connect/ShellDiagnostics.kt:28-29、ShellPhonePicker.kt:15 反向 import ui 包弹窗。
  • 无状态问题集中点：CarPlayMediaKeys.kt:61-80 20 个裸 var；ActiveSessionLog.kt:17-20 仅 @Volatile。

七、优先整改建议（Top 5）

  1. 修 7 个单测失败：3 个环境性（挪走 gitignored offline-mfi 即绿）；4 个 P1 回归（displayScalePercent 断言、VideoView 重建 slot 释放、Codec detach Surface）——与本轮远端基线一并核对。
  2. 单例泄漏兜底：DiPlayActivity.onDestroy 加 TerminalOverlay.dismiss(this)；FloatingBall.hide() 末尾清空 onTap/onLongPress lambda。
  3. Wi-Fi 广播全生命周期注销：FragmentHome.onPause/onDestroy 调 stopWifiWatchers。
  4. CarPlayAppPanels.kt 收编：硬编码色/字号 token 化 + 启动 tile 接 attachRowFeedback + isFocusable（车机方向盘可达）。
  5. 前台通知走 R.string：DiPlaySessionService 三处英文文案入 strings.xml。
